# 比赛阶段、战术数据与激活提示

依据 2027 通信协议 V1.0.0 §2.2.3–2.2.7。消息已由协议和状态模块处理，当前由 `TerminalViewModel`、`EventListModel` 适配界面；QML 不另行订阅或解释 Protobuf。

## 比赛阶段（GameStatus）

| 阶段 | 展示 |
| --- | --- |
| 0 未开始 | 显示顶部状态，不弹倒计时 |
| 1 准备 | 复用 RM26 准备框与服务器倒计时；最后 15 秒使用红色框 |
| 2 自检 | 自检提示与服务器倒计时 |
| 3 五秒倒计时 | 复用 freeze_5 至 freeze_1；0 使用 freeze_start |
| 4 比赛中 | 明确观察到 3→4 时，开始图保留 1.2 秒；中途接入不重播 |
| 5 结算 | 按明确的 game_result 显示红方胜利、蓝方胜利或平局，显示当前局号、比分和 end_reason |

暂停优先于准备、倒计时、开始提示，复用黄色暂停框。结算阶段的 end_reason=6 若没有有效胜者则使用中性异常终止提示；若同时给出有效 game_result，则显示该明确胜者和异常结束原因，不擅自丢弃结果。缺失、255 或未知的胜者不会按比分、基地血量猜胜负，而是等待裁判结算；结束原因覆盖 1–7，未知编号显示原编号。

只有新鲜的有效状态能驱动阶段界面；断线、过期、retained、换局和新会话会移除不再有效的提示。负数或超过五秒的阶段 3 时间不会拼接无效图片或伪装为“开始”。战报可收起，同一连接和局次、相同结算结果的周期消息不会把它重新弹出。胜利动画仅在本次连接、同一局内观察到比赛阶段 4 切换到结算阶段 5 时播放一次，之后停留在末帧；允许胜者延迟上报。启动、重连或换局后直接收到结算状态只静态显示末帧战报，不重播历史胜利；隐藏后不持续播放。

素材来自 RM26 的 `gamephase/` 和 `resultpanel/`，已独立打包到 LY27。红蓝胜利帧保留原先内容，采样成各 34 帧、960×540。旧版异常图片内写有“主裁判终止比赛”，因此不用于 27 的异常结束：平局和异常终止改用中性结算文字，避免擅自归因。界面以 40 ms 换帧，按比例缩放，不依赖 WebP 插件，不预加载整套解码图片。未接入旧版胜负推断、旧机器人战报数值、音效或键盘快捷键。

机制倒计时使用六个固定显示槽位，仅更新内容与可见性，不随秒数变化销毁提示框及背景 Canvas；展示适配单独通知机制列表变化，无关状态刷新不驱动该列表，避免倒计时背景闪烁。

## 底部战场分析（GlobalUnitStatus / GlobalLogisticsStatus）

控制度净速度位于“累计控制度”标题右侧，只显示己方相对对方的一个有符号数；累计伤害保留红蓝柱和数值，不再显示速度。保持现有分析板高度和放大的数字、柱条。

累计控制度和累计总伤害各用一张对比卡，红蓝两条水平柱共享当前双方最大值作为刻度，同时保留真实累计数字。这是长度比较，不是控制率或目标完成率。分析板横跨整个底部，事件栏在其上沿结束。后勤卡上排并列显示我方当前经济（`remaining_economy`）与累计经济（`total_economy_obtained`），下排将科技和加密等级放在同组相邻双格；窄窗口将后勤组放到图表下方。

己敌字段按通信身份映射为红蓝方，切换地图视角不改变归属。累计经济使用十进制文本传入 QML，保留 uint64 整数精度。经济、科技等级和加密等级仅显示己方，不构造敌方数据。合法零值显示 0，缺失、过期、断线与旧连接显示“—”；控制度、伤害和后勤数据独立计时。

控制度净速度根据当前阵地控制状态直接计算，不对累计控制度或伤害差分，不取五秒均值。依据规则 5.6.2（印刷页 97 / PDF 第 98 页），同一方控制两个前哨阵地得 1 点/比赛秒，控制两个基地阵地得 3 点/比赛秒，可叠加。显示值为“己方得分速度 − 对方得分速度”，例如己方控制两个前哨阵地而对方控制两个基地阵地，显示 `−2 点/s`。正值绿色 `#60D8B7`，负值亮红色 `#FF737A`，零与未知为灰色；与地图视角无关，不受模拟器现实时间快进倍率影响。

占领枚举按通信协议 2.2.4（印刷页 54 / PDF 第 55 页）相对于当前通信身份解释：R/B 前哨状态 1/2 均归己方，3/4 均归对方；己方基地状态 1 归己方、2 归对方；对方基地状态 1 归对方、2 归己方。临时控制也计入控制。只有比赛阶段、暂停标记和四个占领字段均有效时计算，暂停时速度为零，缺失/非法枚举/过期/断线/换局/retained 显示未知；恢复后首条完整状态立即计算。累计控制度本身仍直接显示服务器值，不自行累加。

顶部信息条压缩约 12%，窄窗口高度从 232 px 调为 196 px；分析板宽屏高度 148–170 px，窄内容区 184–194 px。地图继续等比例填满剩余区域。

## 击杀与前哨站摧毁播报

复用 RM26 `BattleMessageWidget` 的阵营底框、机器人头像、圆形车号、头像—文字—头像构图及前哨站图标。`BattleAnnouncementItem` 把相同绘制方式接到 Qt Quick，不引入 QWidget 或旧 GameData。播报固定在地图上方中央，绘制在统一通告框的上层，不随提示框数量向下避让；鼠标穿透，显示三秒后用 500 ms 淡出。与 26 一样，新播报立即替换旧播报；所有事件仍完整保留在左侧历史栏。

仅实时有效 Event 1 触发击杀，参数按“被击毁机器人,击杀者”解析；未知/自毁/系统击杀显示“阵亡”，不杜撰攻击者。Event 2 的 11/111 分别触发红/蓝前哨站“被摧毁”。不通过血量首包为零来推断刚发生摧毁，不重播历史和 retained 事件。断线、换局、新会话、暂停或离开比赛阶段清除中央提示。

沿用 26 的 10 秒连续击杀间隔，支持双杀至五杀；机器人阵亡后清除其连杀计数，重连/换局清空统计。只有客户端观测到本局准备/倒计时或明确开局时刻，才对首次有效敌对击杀标注“第一滴血”，中途连接不推断全场首杀。这些是本地展示统计，不是协议额外字段。

当前复用图形播报；26 中引用的 `dead.wav`、`firstblood.wav` 和 `2kill.wav` 至 `5kill.wav` 在参考仓库中缺失，因此没有加载这些语音，也不增加音频依赖。

## 激活计时（GlobalSpecialMechanism）

参考 RM26 `TacticalEventPopup.qml` 的倒计时形式，复用 `HudPanel.qml` 切角面板。消息直接显示在地图上方，最多三列，多项同时显示，空间不足时可滚动，不因只取第一项而漏掉其他计时。按当前秒数从小到大排列，己方推进用绿色、敌方推进用红色。

| ID | 目标与方向 |
| --- | --- |
| 1 | 敌方激活己方堡垒 |
| 2 | 己方激活敌方堡垒 |
| 3 | R 前哨阵地；正数己方，负数敌方 |
| 4 | B 前哨阵地；正数己方，负数敌方 |
| 5 | R 基地阵地；正数己方，负数敌方 |
| 6 | B 基地阵地；正数己方，负数敌方 |

依用户需求，界面把时间参数的绝对值显示为“己方/敌方还有 X 秒激活某阵地”。原文只写“时间参数”，尚未明确区分剩余时间与累计进度，因此这是当前联调显示约定：不自行套用 5/10 秒阈值反算，不用客户端时钟继续扣减，也不凭计时为 0 宣布阵地已经易主。后续若真实引擎明确该参数为累计进度，只需调整展示转换。

0 不显示推进提示；收到空列表、两个数组长度不一致、对应项消失、非战斗阶段、暂停、过期、断线或换局时清除。未知编号暂不展示，原始消息继续记录；重复编号只保留一项。

## 本地验证

重新启动两端后，`LY27_Server` 的“一键演示”会经历准备/倒计时、比赛及结算，经济按服务器实际增加。快速演示会压缩阵地计时的现实持续时间，观察完整五秒过程可选择完整演示。阶段框、双方胜利、平局、异常终止也可通过原控制台设置阶段/结果测试。

模拟服务器会从已有四阵地占领进度生成机制 3–6：以距下次控制状态转换的剩余秒数作参数，符号相对当前服务身份；暂停、双方争夺暂停或进度退回时不发推进项。这只复现现有模拟状态，不实现真实 RFID 检测。堡垒 1/2 沿用原面板手动设置。

手动验证多项提示，可在工作区另开终端执行：

```bash
curl -X POST http://127.0.0.1:8000/api/action \
  -H 'Content-Type: application/json' \
  -d '{"action":"inject","data":{"topic":"GlobalSpecialMechanism","payload":{"mechanism_id":[1,2,3,4,5,6],"mechanism_time_sec":[9,8,3,-4,2,-1]},"hold":true}}'
```

需先进入比赛中且未暂停。`hold` 会持续覆盖该主题，测试结束使用 `clear-overrides` 或控制台重置恢复自动输出。

`test_presentation` 覆盖阶段互斥、真实素材加载、结算帧播放与收起、全部六类机制、红蓝身份/视角、缺失/过期/断线/换局，以及新战术字段；截图写入 `build/local-dev/tests/test-artifacts/phase-*.png`、`mechanisms-*.png`。事件与收入测试见 `events-notes.md`。
