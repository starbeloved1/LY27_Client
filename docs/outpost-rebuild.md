# 前哨站拥有方与重建显示

依据 2027 规则 V1.0.0 §5.6.1（印刷第 94 页）和 §5.6.2 表 5-21（第 96 页），只有通过击毁前哨站，使阵地的完全控制方发生更替，才会为新方重建前哨站，恢复 500 点血量。临时控制不能改变建筑拥有方；基地不套用该规则。

## 输入与判定

当前协议 `GlobalUnitStatus` 提供 R/B 前哨的血量与对应阵地控制状态，没有单独的建筑拥有方字段。枚举 1/4 为己／敌完全控制，2/3 为己／敌临时控制；先按通信身份转为绝对红蓝，地图旋转不影响归属。

`TerminalViewModel` 为两处前哨保存最后一次确认的建筑拥有方：

| 同步情形 | 建筑显示 |
| --- | --- |
| 蓝方原建筑存活，红方临时控制 | 仍为蓝色 |
| 蓝方夺回上述临时失地，恢复蓝方完全控制 | 仍为蓝色，不视为重建 |
| 建筑被击毁，阵地尚为临时控制 | 保留最后确认的建筑颜色，血条使用真实零血量 |
| 新的完全控制方已上报存活血量 | 建筑图标、血条改为该完全控制方的颜色 |
| 已重建的红方建筑又被蓝方临时控制 | 仍为红色 |
| 再次通过击毁使蓝方完全控制，建筑恢复存活 | 改回蓝色 |

完整控制权换方在规则上已包含击毁条件。由于同步只有 1 Hz，不要求必须先收到一次 HP=0；否则会漏掉一秒内完成击毁与重建的合法情况。首次接入时，新鲜的完全控制＋存活快照可直接恢复当前拥有方；首次只收到临时控制时无法判断建筑属于原方还是已重建方，使用灰色未知，不猜测。已有确认归属则在同一连接内跨临时控制保留。血量和控制状态失效时显示未知，重连／新会话／换局清除归属历史。

这里只调整显示：血量始终读取服务器，不在客户端补写 500，也不自行改变血量上限。位置、R/B 名称及官方 ID（11/111）固定，不随颜色改名或改号；既有地图指令 ID 语义保持不变。战术主图与图传小地图共用 `BattlefieldMap.qml`，不会两处各推断一套拥有方。

## 本地验证

`player_ui` 在两种通信身份下覆盖存活临时占领／夺回、零血量、500 血重建、反复重建、跳过零血快照、首次完全与临时快照、旋转、过期、retained、断线重连与换局。图标路径、血条颜色和服务器血量同时验证。模拟器本身已经提供前哨重建规则，可用控制点和伤害面板联调；不以客户端 UI 反向修改模拟状态。
