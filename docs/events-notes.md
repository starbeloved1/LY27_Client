# 左侧战场事件

侧栏由 `EventListModel` 和 `EventPanel.qml` 组成，读取 `StateStore` 的类型化 `EventNotice` 与后勤累计收入，不另建 MQTT 订阅或解析原始协议。

## 显示规则

参考 RM26 的 `GameData::addSystemMessage`、`MessageNotificationPanel.qml`：按收到的顺序追加，最多保留 50 条，新增时滚动到末尾，支持滚轮查看旧消息；长文案自动换行。己方受损/敌方有利用亮红色 `#FF737A`，提升深色背景下的可读性；己方有利用绿色 `#60D8B7`，普通通知为 `#E5E5E5`，金币收入为白色 `#FFFFFF`。颜色表达事件对当前身份的影响，不代表事件所属阵营。

事件时间在接收时固定。比赛计时有效且与事件属于同一连接/局次时显示比赛剩余时间；否则显示接收时间，并在每条记录明确标注时间来源。后端先启动、后创建界面时，从已有通知恢复历史，无法还原当时比赛计时的记录使用接收时间。

断线保留历史，不把事件当成仍在生效的实时状态。新连接的数据继续追加；换局或新会话清空列表。retained 不作为新事件展示；内容和时间相同的两次通知仍保留两条，不擅自去重。未知编号、参数错误显示编号和原参数（最多 256 字符），不解析 HTML。

事件不会乐观修改基地血量、阵地控制、机器人存活或装配结果，实时状态继续由对应消息维护。此列表不接入声音，不从血量变化伪造击杀等官方事件。阶段界面与激活计时提示见 [比赛展示说明](match-presentation.md)。

## 新赛季文案

依据通信手册 V1.0.0 第 2.2.7 节，支持 Event 1–16：击杀、前哨摧毁、大能量机关灯臂/平均环数、能量机关激活、R/B 前哨阵地控制、R/B 基地阵地控制、飞镖命中、敌方闸门开启、基地受击、敌方前哨停转、敌方护甲展开、重装战亡临时激活、装配结果和重装安装模块化 42mm 发射机构。

与 RM26 不同：编号 5–8 是阵地控制事件，14 是重装战亡临时激活，不再套用旧狙击/空中支援/请求四级装配文案。机器人 1 号显示为重装。能量机关激活事件只有类型参数，显示激活类型，不猜测阵营。

## 金币收入观测

RM26 的 `notifyPeriodicRewards` 按旧赛季固定时间点生成“获得金币”，旧版 400/50/150 的数值及空中支援奖励不带入 2027。本项目使用 `GlobalLogisticsStatus.total_economy_obtained` 的实际正增量显示“获得 X 金币”，既覆盖定期收入，也覆盖装配等收入。即使同时发生消费、余额下降，也不会漏记累计收入的增长。

第一条累计总额只建立基线；重复值、总额回退、字段缺失/过期、retained、重连及换局不产生虚假收入。两次有效采样间隔达到 3 秒也重新建立基线，不把断流期间累计值冒充即时收入。只有新鲜的比赛中状态才生成提示，不把准备或结算阶段手动调数当作比赛收入。金额以 C++ uint64 计算，超过 JSON 精确整数范围也能正确计算增量。

收入记录为界面本地通知（模型编号 0），不冒用官方 Event 1–16、不发布回服务器，与官方事件共用最近 50 条列表。晚创建界面仅恢复已有官方事件，并以当前累计收入建立新基线，不还原缺少历史样本的金币记录。

## 本地测试

重启独立 `LY27_Server`，在 Web“事件通知发送”输入 ID 和参数。例如：

| ID | 参数 | 含义 |
| --- | --- | --- |
| 1 | `1,101` | 蓝方重装击毁红方重装 |
| 5 | `2` | R 前哨阵地红方完全控制 |
| 6 | `4` | B 前哨阵地蓝方完全控制 |
| 9 | `1,3` | 红方飞镖命中基地随机固定目标 |
| 11 | 空 | 基地受击 |
| 14 | 空 | 重装战亡临时激活 |
| 15 | `0` / `7` | 装配成功 / 未检测到能量单元 |
| 16 | 空 | 重装安装模块化 42mm 发射机构 |

模拟器手动事件入口和演示均按 2027 编号输出，不使用旧版狙击或空中支援事件。

验证包括文案与颜色、零/缺失/异常参数、重复通知、50 条上限、时间来源、retained、重连/换局/会话隔离，以及侧栏与地图的布局和真实 MQTT 接收。

Event 1/2 除左侧历史外，已接入 RM26 样式的击杀与前哨站摧毁图形播报；只消费实时事件，三秒后淡出，生命周期和首杀/连杀展示策略见 [比赛展示说明](match-presentation.md)。
