# 左侧战场事件

侧栏由 `EventListModel` 和 `EventPanel.qml` 组成，读取 `StateStore` 的类型化 `EventNotice`，不另建 MQTT 订阅或解析原始协议。

## 显示规则

参考 RM26 的 `GameData::addSystemMessage`、`MessageNotificationPanel.qml`：按收到的顺序追加，最多保留 50 条，新增时滚动到末尾，支持滚轮查看旧消息；长文案自动换行。己方受损/敌方有利用红色，己方有利用绿色，其他用中性色。颜色表达事件对当前身份的影响，不代表事件所属阵营。

事件时间在接收时固定。比赛计时有效且与事件属于同一连接/局次时显示比赛剩余时间；否则显示接收时间，并在每条记录明确标注时间来源。后端先启动、后创建界面时，从已有通知恢复历史，无法还原当时比赛计时的记录使用接收时间。

断线保留历史，不把事件当成仍在生效的实时状态。新连接的数据继续追加；换局或新会话清空列表。retained 不作为新事件展示；内容和时间相同的两次通知仍保留两条，不擅自去重。未知编号、参数错误显示编号和原参数（最多 256 字符），不解析 HTML。

事件不会乐观修改基地血量、阵地控制、机器人存活或装配结果，实时状态继续由对应消息维护。当前不接入声音、弹窗或基于状态变化推断的新事件。

## 新赛季文案

依据通信手册 V1.0.0 第 2.2.7 节，支持 Event 1–16：击杀、前哨摧毁、大能量机关灯臂/平均环数、能量机关激活、R/B 前哨阵地控制、R/B 基地阵地控制、飞镖命中、敌方闸门开启、基地受击、敌方前哨停转、敌方护甲展开、重装战亡临时激活、装配结果和重装安装模块化 42mm 发射机构。

与 RM26 不同：编号 5–8 是阵地控制事件，14 是重装战亡临时激活，不再套用旧狙击/空中支援/请求四级装配文案。机器人 1 号显示为重装。能量机关激活事件只有类型参数，显示激活类型，不猜测阵营。

## 本地测试

重启 RM26 模拟器的 `--protocol-profile rm2027` 模式，在 Web“事件通知发送”输入 ID 和参数。例如：

| ID | 参数 | 含义 |
| --- | --- | --- |
| 1 | `1,101` | 蓝方重装击毁红方重装 |
| 5 | `2` | R 前哨阵地红方完全控制 |
| 6 | `4` | B 前哨阵地蓝方完全控制 |
| 9 | `1,3` | 红方飞镖命中基地随机固定目标 |
| 11 | 空 | 基地受击 |
| 14 | 空 | 重装战亡临时激活 |
| 15 | `0` / `7` | 装配成功 / 未检测到能量单元 |
| 16 | 空 | 重装安装模块化 42mm 发射机构 |

模拟器手动事件入口直接输出新格式；自动事件只转发两版含义相同的编号，旧版自动生成的 5–8、14 被过滤，防止错误显示为新赛季阵地控制等事件。默认 rm2026 不受影响。

验证包括文案与颜色、零/缺失/异常参数、重复通知、50 条上限、时间来源、retained、重连/换局/会话隔离，以及侧栏与地图的布局和真实 MQTT 接收。
