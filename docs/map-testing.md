# 战术地图与本地联调

## 当前功能

- 顶部：双方队名、局数/比分、阶段倒计时、暂停提示和双方基地血量；按用户要求已移除前哨站卡片及血量，释放宽度给基地血条。队名来自 `--red-team`、`--blue-team` 本地参数；未知数据显示“—”。基地上限 10000，深色血槽满宽、亮色填充按当前血量比例裁切。保留 R 队徽和状态行，不展示 100% 防御增益文字、图标或护盾金边；状态 1/2 仍分别显示护甲未展开/展开，未收到或过期显示状态未知，零血量显示基地已摧毁。右上 DATA 灯表示比赛计时数据是否新鲜。BO 未给总局数时默认 BO3，局次和比分不补默认值。
- 地图：红蓝双方 1/3/4/7 共八台地面机器人的位置、朝向、等级和血量比例。车标采用阵营色圆形编号，上方为金色细边框的紧凑血条，左侧紧贴等高等级小格，只显示等级数字；不显示具体血量数字。血量或最大血量未知时显示灰框问号，不画假满条；真实零血量为空条。本机使用绿色图标，其他机器人使用阵营颜色。等级与血量不通过坐标消息推断；来自静态属性和全局血量状态。
- 设施：地图两侧中部的红蓝基地和中央道路旁的 R/B 前哨站均采用与车辆同风格的 60×14 细血条，不显示建筑名称、血量数字或等级格。前哨站叠加 RM26 红蓝图标，常规宽 56 px、小地图最多 30 px，并提亮、提高饱和度，不添加光环；基地暂不添加独立图标。未知时为灰框问号，零血量为空条，前哨站摧毁时图标淡化。均直接复用顶部状态字段。标记按原图像素中心归一化定位，随实际图片区域缩放和视角镜像；地图设施未知/过期显示问号，零血量为空条；顶部仅保留基地数字，前哨站血量只在地图显示。图片左上/右下的大 R 标志不作为基地或前哨站。
- 视角：右下角切换红蓝地图视角，只影响展示；图片旋转 180°，机器人同步镜像，文字保持正向，通信身份不变。
- 数据有效性：没有位置不画图标；雷达位置超过 1 秒后淡化，`RobotPosition` 超过三个周期（默认 3 秒）后淡化，距最后有效位置满 5 秒隐藏。断线、换局、旧连接数据和 retained 位置不显示；血量与等级过期显示“—”，不以零代替未知。机器人零血量显示空条，设施零血量显示 0，不擅自解释为存活枚举。

地图坐标沿用 RM26 的左下角原点习惯，暂按 28 × 15 m 投影到图片围挡内近似范围 `(24,24)–(1638,921)`；图标跟随 `Image.paintedWidth/paintedHeight`，不把留白算进场地。底图经过 AI 重建，这只是显示标定，实机前仍需用已知点核对场地坐标方向、范围和设施位置。

顶部信息栏占满整行，原控制度/经济行移到底部分析板。左侧战场事件栏从信息栏下方延伸到分析板上沿，右侧为地图；战场分析板横跨整个窗口底部，左下角也归分析板。事件栏宽度按窗口限制在 170–250 px，分析板宽屏高度为 148–170 px、窄内容区为 184–194 px，顶部信息栏也相应压缩，地图保持等比例填满剩余空间；视角切换和数据状态提示也合入分析板，不再另设独立状态底栏。事件显示规则与模拟器用法见 [事件说明](events-notes.md)。

## 经济和累计控制度

全宽底部战场分析板显示双方累计控制度、累计总伤害、我方当前/累计经济及己方科技/加密等级。当前经济采用 `GlobalLogisticsStatus.remaining_economy`，累计经济采用 `total_economy_obtained`，直接读取服务器上报，只展示当前通信身份所属阵营；累计值不当成余额，也不在客户端自行累加，不构造敌方经济。控制度采用 `GlobalUnitStatus.total_CP_ally/total_CP_enemy`，按身份映射回红蓝方，直接显示服务器累计值，不转换成百分比、不本地累计。控制度和伤害分别以红蓝水平柱对比，保留累计值，伤害不显示增速，控制度按当前阵地状态显示我方净速度；占领枚举、计算和有效性规则见 [比赛展示说明](match-presentation.md)。科技和加密等级归为相邻双格。切换地图视角不会交换通信身份或我方经济。

伤害取 `GlobalUnitStatus.total_damage_ally/total_damage_enemy`，科技和加密等级取后勤的 `tech_level/encryption_level`。经济、控制度、伤害与等级按各自来源独立更新；合法的零显示 0，缺失、断线、旧连接和过期显示“—”。

在 `LY27_Server` 控制台的“比分与经济控制”中可直接调整经济和累计控制度；规则模拟也会根据阵地控制状态累计控制度。直接调数用于验证显示，不表示机器人能通过上行指令修改裁判状态。

## 启动两个程序

在工作区根目录分别打开两个终端：

```bash
./LY27_Server/start.sh
```

```bash
./LY27_Client/start.sh --mqtt --red-team "凌云战队" --blue-team "蓝方测试队"
```

模拟器 Web 控制台：<http://127.0.0.1:8000>。MQTT 为 `127.0.0.1:3333`，LY27 示例配置已经一致，不启用视频端口。Web 可拖动机器人或设置坐标，再修改血量、等级、基地/前哨站血量、比分、局数和比赛阶段观察结果。Web 命令的 `robot_id` 是数组索引 0–7，依次对应真实 ID `1,3,4,7,101,103,104,107`。控制台沿用 26 的格式与界面，内部为独立的 2027 协议和规则子集。已经运行的旧服务和客户端均需先退出再重启。

蓝方身份联调时，需同时将模拟器 `--current-robot-id` 与 LY27 个人配置的阵营、机器人编号和 MQTT 身份对齐。单个模拟器输出的全局数组只服务一种阵营视角，不能让红蓝身份同时共享它并期待正确的己敌映射。显示视角按钮与身份切换是两回事。

## 雷达位置联调约定

默认 `--position-scope map-test`，服务器以 **10 Hz** 发布 `RadarInfoToClient` 八车汇总；`RobotPosition` 只给当前机器人（指挥手为己方哨兵）发布，默认 **1 Hz**。地图依次经过雷达解码、编号映射和厘米转米，复用现有位置动画。八车等级/血量上限仍由地图测试模式的 `RobotStaticStatus` 提供，当前血量来自全局状态。

雷达顺序是敌方 1/3/4/7、己方 1/3/4/7，和全局血量的己先敌后顺序不同。两端都按通信身份映射；切换显示视角不改变身份。`RobotPosition` 与雷达并存时，采用较新的有效、新鲜坐标，防止旧来源把标记拉回。雷达不提供朝向，其他机器人的朝向不作推断。

`RadarInfoToClient` 的原文外层不能编译，现按用户要求采用本地暂定 `repeated RadarSingleRobotInfo robot_info = 1`。外层和 10 Hz 都是联调约定，不能据此确认正式服务器格式、权限或可用范围。详见 [协议说明](protocol-notes.md)。客户端不加入 2026 协议兼容。

可用 `--radar-hz 0` 关闭默认雷达生成，或用 `--radar-hz 5` 调整测试频率；范围 0–20 Hz。`--position-hz` 只调整当前目标的直接位置频率。`--position-scope official` 不生成暂定雷达、只发送当前目标的位置和静态属性，并限定直接位置 1 Hz；它不等于完整复现官方权限或路由。

## 代码连接

`MQTT → MessageCodec → StateStore → TerminalViewModel / RobotMapModel → QML`。

`apps/desktop/src/main.cpp` 管理配置、日志与运行生命周期；`modules/ui/src/TerminalViewModel.cpp` 适配比赛/设施信息，`RobotMapModel.cpp` 提供八行地图模型；`Map.qml` 组合底图、顶部和标记，`FacilityMapMarker.qml` 显示地图建筑血量，`MatchHeader.qml`、`BattleAnalysisPanel.qml`、`MatchResources.qml`、`BaseHealthWing.qml`、`BaseHealthBar.qml`、`OutpostStatusBadge.qml`、`RobotMarker.qml` 分别负责具体显示。UI 不解析原始协议，不另建通信对象。

测试包含暂定雷达的固定字节格式、敌先己后编号映射、厘米转米、双位置来源选择、仅雷达驱动的红蓝八车 QML 标记，以及零值/缺失、全局血量映射、镜像、过期/断线/重连/换局，以及七种窗口尺寸（含超宽屏和 640×480 最小窗口）下的 QML 渲染、顶部文字边界/重叠、等级格与血条紧贴、设施血量数字、血条比例和实际图片范围。测试截图位于构建目录 `tests/test-artifacts/hud-*.png`。另使用真实本地 Broker 和模拟器 Web 命令验证位置、等级和血量穿过完整链路。本次真实 LY27_Server → MQTT → C++ CLI 联调在 3.5 秒内收到 34 帧八车雷达，均解析成功且坐标持续变化；直接位置仅发送当前 3 号，八车雷达也均进入状态存储。客户端 12 组测试、服务器 36 项测试通过；新增雷达地图用例单独复验通过。尚未通过官方赛事系统验证。

比赛准备/暂停/倒计时/胜负结算、上方激活提示及新增战术字段见 [比赛展示说明](match-presentation.md)。
