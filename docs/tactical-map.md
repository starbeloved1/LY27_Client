# 地图点选与标记同步

## 启动与操作

在客户端根目录运行 `./start.sh`，自动连接本地模拟服务器。右上角设置选择指挥手或对应操作手，并选择红蓝方；不再使用 `cao`、`zhi` 和 `--mqtt` 启动参数。可用 `--config` 读取不同初始身份与连接配置。

指挥手不绑定机器人，所有车辆按红蓝方显示，没有绿色本机车。切换身份会清理旧数据和指挥选择，并重连等待新消息。多窗口联调应分别准备配置，填写不同 MQTT Client ID；该 ID 是显式连接配置，不按车号或角色生成，不自动写回配置。

指挥手先点击一台有新鲜位置的己方车，车标变金色，表示接收者。然后：

- 点击基地或前哨站：按 ID 所属阵营自动选择己方防御、对方攻击。
- 点击空地：在点击处上方选择攻击、防御或警戒。
- 点击敌车：选择攻击或警戒。
- 点击己车：直接选择防御，包括保护被选车辆自身。

提交成功后清除选择，开始下一条指令；右键或 Esc 随时取消。限频或离线失败保留选择并显示原因，不缓存、不自动重发。发送间隔共用现有 `CommandDispatcher` 的指挥手 500 ms 限制。MQTT 接受提交不表示同步成功，地图标记只在收到 `MapClickInfo` 后显示。

## 字段与本地约定

依据工作区通信协议 V1.0.0，§2.2.17／18 见印刷页 65–67，ID 见附录二印刷页 79。不修改 `.proto` 或字段号。`MapClickCmd` 发布，模拟服务器以相同字段回送 `MapClickInfo`。

| 字段号 | 字段 | 当前填写方式 |
| --- | --- | --- |
| 1 | `is_send_all` | 固定 1 |
| 2 | `robot_id` | 选中接收车的单字节 ID，后补六个零，总长七字节，不是 ASCII 数字 |
| 3 | `mode` | 攻击 1、防御 2、警戒 3 |
| 4 | `enemy_id` | 实体目标填其官方 ID；坐标模式不使用 |
| 5 | `ascii` | 普通标记不填写 |
| 6 | `type` | 地图点 1、实体 2 |
| 7／8 | `map_x`／`map_y` | 地图点使用场地米坐标；实体目标显式填零 |

车辆使用 1／3／4／7 和 101／103／104／107，基地 10／110，R／B 前哨 11／111，均已有官方 ID，不另造编号。前哨默认攻击／防御按 ID 所属阵营处理，不随阵地临时控制改变目标编号。

用户要求范围固定为 1、再由接收端按列表筛选，因此允许范围 1 携带接收者。协议文字中范围 1 是“除哨兵”，本地显式列表优先，选择 7／107 时也照此生成并筛选；真实赛事服务是否向哨兵转发仍需官方确认。全零列表则兼容广播语义：1 接收重装和两台步兵，2 额外包含哨兵，0 必须有接收者。列表中不允许重复、跨阵营或零后再出现有效 ID。

官方 `type=2` 文字仅描述对方机器人。用户要求标记己车及建筑，本地显式增加 `MapEntity`，复用这一模式与现有 `enemy_id` 字段承载己方实体和建筑 ID，客户端与 `LY27_Server` 同步支持；原 `MapEnemy` 保持敌车限制。此扩展和范围列表的解释均是当前本地联调约定，不宣称官方已经支持；后续可集中在指令与模拟器处理处调整，勿改字段号或生成文件。

## 接收与显示

`TacticalMapController` 读取 `StateStore::roleState().lastMapMarker`，不绕过状态层解析载荷。操作手只接受目标列表包含本车的消息；指挥手显示同队回送标记，并在旁标出接收车号。不同接收者的标记分别保存，每个接收者以最新有效标记替换旧标记。

标记使用黄黑色剑／盾／感叹号。地图点由坐标转换定位；车辆目标跟随同一位置来源并采用与车辆相同的短平滑动画，放在等级／血条上方；建筑目标在设施血条上方。实体位置未知或过期时隐藏，不在零坐标补画。红蓝视角翻转同时作用于目标、弹窗和标记，发布坐标仍使用绝对场地坐标。

每条标记显示 10 秒，这是当前本地显示策略，协议没有规定该时长。只响应本次实时消息，创建窗口不补播历史，retained 不触发；断线、会话重置与换局清空，重连不恢复旧标记。缺失、非有限／越界坐标、非法 ID／类型／列表不会覆盖已有有效标记。

## 验证

`tactical_map` 使用独立 Broker、三套后端与真实 QML 鼠标点击，检查发布字段、接收者筛选、车辆／建筑目标、跟随、弹窗与图标、无绿色指挥手车标；另以可控时间检查十秒过期、位置失效、retained、断线和换局隔离。截图在 `build/local-dev/tests/test-artifacts/tactical-map-*.png`。`commands` 覆盖双方 ID、扩展校验和共享限频；模拟器规则测试与真实 Web／MQTT 集成测试覆盖接收和回送。

位置刷新时以固定接收车槽位更新标记坐标，不用变化的数组重建 QML 标记；增加 Buff 行时标记上移避让。己方防御目标持续移动的图标生命周期回归见 `test_buffs`。
