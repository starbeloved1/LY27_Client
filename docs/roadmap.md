# 功能接入路线

## 1. 工程基础（已完成）

- 独立的 C++17 / Qt Core 后端和命令行程序。
- 严格校验配置，分开保存角色、阵营、席位、机器人和 MQTT 身份。
- 明确的启动、停止和会话编号，支持重复调用及后续重启。
- 标准输出为可解析状态，标准错误和文件保存日志。
- 无显示服务器运行；配置错误、日志失败、正常退出有独立结果。

## 配置重载与身份切换（已接入）

`TerminalRuntime` 提供配置应用、文件重载、显式身份切换、配置保存与可选文件监听。运行中变更使用原通信启用组合建立新会话；无效配置不打断当前会话，同步初始化失败恢复旧配置，恢复也失败时明确保留停止状态。状态、指令和视频对象保持稳定，清除旧会话数据与未确认操作，不重发业务指令。

CLI 新增 `--watch-config`，适配编辑器原子保存与删除重建；日志目录和等级同步更新。配置保存独立执行，使用原子替换，另存时保持日志目录指向。接口和测试范围见 `config-notes.md`。

## 2. 官方协议与 MQTT（已接入）

已加入独立 `.proto`、32 个 Topic 的方向/频率清单、Protobuf/Paho 构建目标、异步传输、23 个入站订阅、23 类入站消息解析和原始记录。`RadarInfoToClient` 按用户授权以本地暂定外层补全，保存来源标记，详见 `protocol-notes.md`。

通信层提供通用发布接口并进行本地往返测试；赛事业务发布入口已在第四步集中接入，通信层仍不解释业务。

MQTT 模块负责连接、订阅、收发和重连；协议层负责编解码。连接、发送、断开和客户端销毁在受控执行上下文完成。默认离线，使用 `--mqtt` 显式开启连接。已完成本地 Broker 联调，真实赛事引擎的身份、权限及消息条件仍待核实。

## 3. 状态管理（已接入存储与 C++ 业务结构）

已增加 `modules/state/`，模块内部独立划分 `include/` 和 `src/`。`StateStore` 保存全局、本机、各机器人和角色相关状态，每个样本带来源、会话、接收时间和有效性；通过 `TerminalRuntime::stateStore()` 查询，`stateChanged` 通知变化，运行快照的 `business_state` 用于 CLI 检查。

已处理字段存在性、周期数据过期、Buff 独立到期、断线失效、重连等待更新、重启清空、红蓝方全局血量映射、指挥手无本机编号和最近 128 条事件类通知。

业务层已提供 `MatchState`、`GlobalState`、`RobotState`、`RoleState` 与有明确类型的通知，直接从 Protobuf 存储样本转换，不依赖 JSON 字段查找。机器人状态汇总静态属性、实时数据、模块、位置、复活、受伤、判罚、性能选择、Buff 和自定义字节；派生血量/热量/复活进度比例，全部输入来源独立计时。缺失值用 `std::optional` 表达，不把未知当作零；不把血量零直接解释为服务器存活枚举。

明确收到非 retained 的局次变化时清空上一局状态、Buff 与通知，保留连接和会话。JSON Topic 接口仍保留作诊断；原始载荷仍由第二阶段记录链路保存。机器人自定义字节的内部协议、战术分析、定时提醒、界面显示适配不属于本次业务数据结构接入，按实际需求继续增加。

周期超时暂采用三个发送周期且最低 500 ms 的工程策略，后续按真实引擎行为调整；条件通知不因长期未收到而判定故障。详见 `state-notes.md`。状态字段的实机发送条件、完整性和权限仍需赛事环境验证。

## 4. 赛事指令（当前已接入）

已增加 `modules/commands/`，模块内部独立划分 `include/` 和 `src/`，由 `CommandDispatcher` 提供类型明确的装配、性能体系、哨兵控制方式、常用兑换/复活、能量机关、飞镖、哨兵和地图操作。共覆盖七个赛事出站 Topic；键鼠和不解释内容的自定义控制接口仍在协议/传输层预留，实际设备在第六步接入。

已实现角色和参数检查、按 Topic 统一限频、必要状态的新鲜度/允许标记检查、QoS 1 传输确认、失败/断线/超时的未知状态、最近 128 条提交记录、哨兵结果单独观察及发送 JSONL。CLI 通过 `--command-file` 执行单次操作，和未来界面复用同一入口。没有为每个 Topic 建一个服务，也没有添加猜测的业务自动流程。

传输确认与赛事执行结果分别记录：`execution` 保持 `not_confirmed`，不凭 MQTT 发布成功宣布操作完成。哨兵结果按操作种类报告，缺少请求唯一编号，因此不强行匹配某次点击。RFID、经济、次数、准备阶段窗口、姿态冷却等仍由引擎最终裁定，当前不实现无法可靠确认的本地规则推断。地图角色与间隔采用规则允许的本地策略，现场权限仍需核实。

已加入本地 Mosquitto 与无 PUBACK 模拟对端验证，覆盖线格式、角色、参数、状态、限频、传输超时、CLI 和发送记录。详见 `commands-notes.md`。第五阶段图传现已接入。

## 5. 图传（已接入本地验证链路）

已增加独立 `modules/video/`，提供官方 UDP 3334 包头解析、分片重组、H.265 软件解码、最新视频帧与状态接口。支持乱序和重复包、有限缓存、超时清理、16 位帧号回绕、丢帧/错误后等待关键帧，以及停流和重启隔离。UDP、重组和解码运行在专用线程，对外合并通知并只保存最新图像。

`TerminalRuntime::start(enableMqtt, enableVideo)` 管理启停；CLI 通过 `--video` 独立启用，`--save-frame` 导出首张新鲜 PNG。默认只监听回环地址，可配置现场监听地址和来源 IP。新增 Qt Gui/Network 与 FFmpeg 开发库依赖，仍无需图形窗口。

本地 C++ 测试已验证真实合成 HEVC 码流、UDP、解码恢复、生命周期与无界面 CLI；尚未验证真实硬件、实际分片和码流边界、1080p60 持续性能。详见 `video-notes.md`。输入设备、自定义控制、记录回放和终端协同按当前安排暂缓；后续优先补齐必要业务能力及桌面接入。

## 后续范围

地图已追加六处阵地范围与流动光带，边框随控制方显示绝对红蓝，完全实线、临时虚线、未知灰白，激活提示叠加推进方高光与秒数，按每侧前哨合并、基地与堡垒分开显示；与底图缩放、视角翻转对齐。当前只提供战术位置示意，车辆／建筑点击已用于地图标记，不根据地图几何推断占领。见 `territory-overlay.md`。

已确定优先规划重装和指挥手的桌面前端，主要提供官方选手端之外的信息辅助。首页参考 RM26 的战术总览，突出地图、双方机器人状态、比赛/设施状态、经济和事件，装配等角色业务作为局部状态或独立面板。代码结构参考 RM26 的角色页面、独立业务面板、公共组件与弹层划分，具体 UI 风格和动效另行设计；默认显示地图，已接入 P 切换带 RM26 选手 HUD 的整窗图传，桌面启动自动接收 UDP，空格按住显示设置、松开或失焦关闭。步兵的后端身份和现有能力保持支持，步兵前端暂缓。详见 `desktop-plan.md`。

桌面已增加可选 Qt Quick 目标 `ly27_desktop`，保留高清场地底图，接入顶部队名、比赛计时、局数/比分与基地血量，前哨站血量仅在地图显示，以及八台地面机器人的位置、等级和血量。左侧追加战场事件列表，参考 RM26 的最近 50 条、时间戳、颜色和自动滚动，按 2027 Event 1–16 解释，详见 `events-notes.md`。地图两侧基地与中央道路旁 R/B 前哨站均只显示车辆同风格细血条，不显示名称与血量数字；前哨站采用放大的 RM26 图标。基地图标暂缓。标记随缩放和红蓝视角切换定位。顶部保留比赛/设施信息；左侧事件栏延伸至分析板上沿，右侧显示等比例地图，横跨整个底部的战场分析板集中显示我方当前/累计经济和双方累计控制度，读取官方状态，不计算敌方经济或把控制度转换成百分比。C++ 展示适配读取已有类型化状态，QML 复用 RM26 图标和信息条素材；缺失、断线与位置超时有明确显示策略，不填模拟默认值。

当前联调改用独立 `LY27_Server`，控制台沿用 RM26，协议与规则按 2027 适配。按用户要求，两端暂定补全 `RadarInfoToClient` 外层：八车按敌先己后排序、厘米转米、特殊标记保存、断线/过期/换局失效。服务器默认雷达 10 Hz，当前目标 `RobotPosition` 1 Hz；不向客户端加入旧协议兼容。雷达外层与频率属于本地测试约定，尚未验证官方赛事链路。详见 `map-testing.md` 和 `protocol-notes.md`。

分割、矢量重绘、设施独立详情和角色专项页面仍暂缓，不把网页原型或素材分割实验标成正式功能。

§2.2.17/18 已接入双模式启动、指挥手地图点选发布与操作手筛选同步；范围列表与己方实体／建筑使用本地协同约定，细节见 `tactical-map.md`。控制输入、自定义控制器、记录回放和其他终端协同继续暂缓，不按编号自动接入。桌面按钮操作与后续操控键鼠连续上传分开，创建桌面窗口不自动开启键鼠或控制器发送。

## 6–9. 后续模块
1. 输入和自定义协议：虚拟输入、确定的外接设备、控制映射与自定义遥测；独立 `modules/input/`，桌面键鼠适配随窗口接入。
2. 记录回放：在前期原始记录上增加消息、遥测、视频和操作的同步回放；独立 `modules/recording/`。
3. 终端协同：共享状态、标记和任务，明确来源、身份和有效期；独立 `modules/team/`。
4. 正式界面：桌面入口放在 `apps/desktop/src/`，界面模块放在 `modules/ui/`；首批重装和指挥手工作台，步兵后续扩展。C++ 展示适配通过状态和操作接口使用已经验证的功能，默认显示地图并接收图传，按 P 切换。

按功能需要增加目录、类型和构建目标，不预先填充空模块，也不引入插件框架或通用事件总线。

所有模块独立维护 `CMakeLists.txt`；只有一个手写头文件和一个实现文件时直接放在模块根目录，多文件模块使用各自的 `include/` 和 `src/`。业务实现、命令行与测试统一使用 C++。协议源文件位于协议模块内，自动生成文件位于该模块的构建目录。
