# 功能接入路线

## 1. 工程基础（已完成）

- 独立的 C++17 / Qt Core 后端和命令行程序。
- 严格校验配置，分开保存角色、阵营、席位、机器人和 MQTT 身份。
- 明确的启动、停止和会话编号，支持重复调用及后续重启。
- 标准输出为可解析状态，标准错误和文件保存日志。
- 无显示服务器运行；配置错误、日志失败、正常退出有独立结果。

## 2. 官方协议与 MQTT（当前已接入）

已加入独立 `.proto`、32 个 Topic 的方向/频率清单、Protobuf/Paho 构建目标、异步传输、23 个入站订阅、22 类入站消息解析和原始记录。`RadarInfoToClient` 因原文歧义暂保留原始数据，详见 `protocol-notes.md`。

通信层已提供通用发布接口并进行本地往返测试；CLI 当前只开放接收观察，不提供装配、兑换等业务发布命令。此类操作仍按第四步接入。

MQTT 模块负责连接、订阅、收发和重连；协议层负责编解码。连接、发送、断开和客户端销毁在受控执行上下文完成。默认离线，使用 `--mqtt` 显式开启连接。已完成本地 Broker 联调，真实赛事引擎的身份、权限及消息条件仍待核实。

## 3. 状态管理

增加 `modules/state/`，模块内部独立划分 `include/` 和 `src/`，保存全局、对应机器人和角色相关状态。每类数据保留来源、接收时间和有效性；未知、断链、过期不替换成虚构状态。协议字段在边界转成内部状态，后续界面读取同一份状态。

## 4. 赛事指令

增加 `modules/commands/`，模块内部独立划分 `include/` 和 `src/`，通过类型明确的方法完成参数检查、限频和消息构造。CLI 和未来界面共用入口，简单命令集中在 `CommandDispatcher`，实际出现复杂流程时再提取流程对象。

传输确认、赛事执行结果和机器人动作反馈分别记录；没有协议结果时标记等待确认或未知，不凭 MQTT 发布成功宣布操作完成。完整覆盖公共及角色相关操作，并由模拟对端核对 Topic、载荷和频率。

## 5–9. 后续模块

1. 图传：UDP 分片、H.265 解码、异常恢复及实际性能验证；独立 `modules/video/`。
2. 输入和自定义协议：虚拟输入、确定的外接设备、控制映射与自定义遥测；独立 `modules/input/`，桌面键鼠适配随窗口接入。
3. 记录回放：在前期原始记录上增加消息、遥测、视频和操作的同步回放；独立 `modules/recording/`。
4. 终端协同：共享状态、标记和任务，明确来源、身份和有效期；独立 `modules/team/`。
5. 正式界面：桌面入口放在 `apps/desktop/src/`，界面模块放在 `modules/ui/`，提供重装、步兵、指挥手工作台。Qt/C++ 界面通过状态和操作接口使用已经验证的功能。

按功能需要增加目录、类型和构建目标，不预先填充空模块，也不引入插件框架或通用事件总线。

所有模块独立维护 `modules/<模块>/include/`、`modules/<模块>/src/` 和 `CMakeLists.txt`；业务实现、命令行与测试统一使用 C++。协议源文件位于协议模块内，自动生成文件位于该模块的构建目录。
