# 功能接入路线

## 1. 工程基础（当前阶段）

- 独立的 C++17 / Qt Core 后端和命令行程序。
- 严格校验配置，分开保存角色、阵营、席位、机器人和 MQTT 身份。
- 明确的启动、停止和会话编号，支持重复调用及后续重启。
- 标准输出为可解析状态，标准错误和文件保存日志。
- 无显示服务器运行；配置错误、日志失败、正常退出有独立结果。

## 2. 官方协议与 MQTT

逐项核对 2027 官方消息，建立 `.proto` 和 Topic/方向/频率清单。增加 `protocol/`、`src/protocol/`、`src/transport/mqtt/`。接入 MQTT 时才加入 Protobuf、Paho 依赖和独立构建目标。

MQTT 模块负责连接、订阅、收发和重连；协议层负责编解码。连接、发送、断开和客户端销毁在受控执行上下文完成。真实连接前验证 `mqtt_client_id`，指挥手身份按实际赛事入口核实。先与本地模拟对端联调，记录原始收发消息和接收时间。

## 3. 状态管理

增加 `src/state/`，保存全局、对应机器人和角色相关状态。每类数据保留来源、接收时间和有效性；未知、断链、过期不替换成虚构状态。协议字段在边界转成内部状态，后续界面读取同一份状态。

## 4. 赛事指令

增加 `src/commands/`，通过类型明确的方法完成参数检查、限频和消息构造。CLI 和未来界面共用入口，简单命令集中在 `CommandDispatcher`，实际出现复杂流程时再提取流程对象。

传输确认、赛事执行结果和机器人动作反馈分别记录；没有协议结果时标记等待确认或未知，不凭 MQTT 发布成功宣布操作完成。完整覆盖公共及角色相关操作，并由模拟对端核对 Topic、载荷和频率。

## 5–9. 后续模块

1. 图传：UDP 分片、H.265 解码、异常恢复及实际性能验证；独立 `src/video/`。
2. 输入和自定义协议：虚拟输入、确定的外接设备、控制映射与自定义遥测；独立 `src/input/`，桌面键鼠适配随窗口接入。
3. 记录回放：在前期原始记录上增加消息、遥测、视频和操作的同步回放；独立 `src/recording/`。
4. 终端协同：共享状态、标记和任务，明确来源、身份和有效期；独立 `src/team/`。
5. 正式界面：增加 `apps/desktop/` 和 `src/ui/`，提供重装、步兵、指挥手工作台。QML 只通过状态和操作接口使用已经验证的功能。

按功能需要增加目录、类型和构建目标，不预先填充空模块，也不引入插件框架或通用事件总线。
