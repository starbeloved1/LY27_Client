# 27 醒目播报与 RM26 取舍

操作手与指挥手 共用提示，不播放语音。以本地 2027 规则 V1.0.0（20261015）与通信协议 V1.0.0（20261029）为依据。

## 固定时间节点

表中时间为开局后经过时间。文案按用户要求采用“可激活／可开启”，只表示规则节点到达，不保证未消耗次数、冷却等条件满足，也不等于实际激活或开闸。

| 文案 | 比赛节点 | 剩余时间 |
| --- | --- | --- |
| 可激活小能量机关 | 0:00、1:30 | 7:00、5:30 |
| 可激活大能量机关 | 3:00、4:15、5:30 | 4:00、2:45、1:30 |
| 可开启飞镖闸门 | 0:30、4:00 | 6:30、3:00 |
| 本局比赛剩余 X 秒 | 最后五秒 | 0:05–0:01 |

不再提前显示能量机关激活或飞镖闸门开启倒计时；连续观测到固定节点后才显示“可激活／可开启……”约三个比赛秒。比赛最后五秒提醒单独保留。使用同局、同连接且新鲜的服务器比赛时钟，经过时间与剩余时间之和必须为 420 秒；不补播快进、中途加入、重连和过期恢复所错过的节点。暂停、非战斗及时间无效时隐藏。同局节点去重，准备阶段或换局重置。

## 专用结果面板

移除原 Event 3–16 通用实时事件框，改为参考 RM26 专用面板的信息结构：醒目结果、统计或目标详情；保留左上分类标签，所有通告均不加右上角标，结果面板也不加“服务器确认激活”等说明，无详情时结果在内容区单行居中。能量机关与飞镖各有独立槽位，可同时展示，不互相覆盖；仍参与机制提示、固定节点的横向排列、换行与纵向滚动。左侧事件历史仍记录完整 Event 1–16 及收入，击杀／前哨摧毁横幅保持原实现并覆盖在提示上层。不接入无人机被照射提示，也不生成该事件记录。

协议 §2.2.7（印刷页 57）的实际结果：

- Event 4 参数 1/2：小／大能量机关进入已激活状态，显示“……已激活”，停留六秒。
- Event 3：仅大能量机关完成时触发，提供成功灯臂数量、平均环数，显示“成功灯臂 X · 平均环数 Y”。这是完成结果，不是连续进度。与仍在展示的大能量类型通知合并；补齐统计不重播动画，后到的类型通知不抹去统计。
- Event 9：命中方 1 红／2 蓝，目标 1–5 分别为前哨站、基地固定、基地随机固定、基地随机移动、基地末端移动目标，显示“己方／敌方飞镖命中”与目标名称，停留五秒。

己方飞镖命中为绿，敌方命中为红，相对配置阵营判断，地图翻转不改变利弊。能量机关 Event 3/4 没有单独的阵营字段，但用户已确认该消息默认只提供己方激活结果，因此统一绿色；不再显示“阵营未提供”或额外阵营标签。没有从 Buff 快照拼接本次激活收益，也没有按平均环数反推精确总环数、伤害或加成时长。Event 9 给出命中结果与目标，不直接给本发造成的伤害数值。

`RuneStatusSync.average_rings` 按 §2.2.27（印刷页 71–72）仅大能量机关正在激活时有效，其他状态为零，因此不拿完成后的状态快照覆盖 Event 3 的结果，也不以状态快照触发完成播报。

仅接收当前连接/局次、战斗且未暂停的有效非 retained Event，拒绝缺失或非法参数。连续相同结果不延长展示；同类新结果替换旧结果。暂停、断线、比赛状态失效、会话或局次变化清空。未实现跨多次激活的精确关联，协议事件没有请求或激活唯一编号；当前合并只限同一仍在展示的大能量结果。

## 展示与验证

`MatchNotices` 负责节点、结果解析、阵营判断与生命周期，`EventResultPanel.qml` 显示专用结果；机制和节点继续使用 `BattleNoticeCard.qml`。`AnimatedNotice.qml` 使用稳定槽位保留离场快照，约 420 ms 从上方模糊淡入／上移淡出，离场完成后其余框用 380 ms 平移补位，倒计时刷新不重播。软件渲染保留位移和淡入淡出。

`match_notices` 覆盖节点文案、两种角色与阵营、全部飞镖目标、能量结果两种到达顺序、去重、普通事件只进历史、非法参数、retained、暂停/断线/换局/过期及多尺寸窗口截图。`events` 与 `presentation` 检查历史和击杀/设施播报回归。

## 不迁移的旧逻辑

旧空中支援、英雄狙击、四级装配请求、前哨复活周期与对应旧事件含义不沿用；不从血量变化猜敌方付费复活，不计算未知剩余机会，不播放语音。
