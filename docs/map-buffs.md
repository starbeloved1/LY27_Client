# 地图 Buff 图标

车辆与设施的血条上方新增 14 px 图标行，从左到右按 Buff 类型 1–7 排列；内部原图约 12 px，背景深色。行与等级格左边缘对齐（整组等级＋血条宽 56 px，常规位置以血条本体对中车标，等级格附在左侧），接近地图边缘时整行向内收。Buff 行下沿距血条上沿 2 px，常规位置沿用原有血条与车标间距；上边缘空间不足时整组改放车标下方，Buff 仍在血条上方；战术指令图标同步避开该行。悬停可看实际增益值与剩余时间。

操作手 `cao` 和指挥手 `zhi` 共用地图 Buff 显示。操作手另有地图左下角“本机增益”栏，只读取绑定机器人的增益，不依赖本车位置消息；指挥手不显示本机栏。没有有效增益时隐藏，断线同步清空。

数据由 `StateStore::buffs(entityId)` 提供有来源的 C++ 状态，`mapBuffs()` 统一适配，QML 不解析协议。攻击、防御／易伤、冷却、功率、回血、可兑换允许发弹量和地形跨越预备分别显示。只展示有效且未到期的非零增益；防御负值用易伤图标。清零、剩余时间为零、缺字段、retained、断线、前连接和换局不继续显示。

素材复制自 RM26，已编入当前客户端，不依赖旧项目运行路径。图像提供器取符号部分，裁去旧版固定百分比／倍率文字，避免将 26 的增益等级映射套到 27 的实际数值。功率借用旧版机动符号，弹量使用旧版弹药符号，其余使用对应 Buff 素材；真实数值保存在展示数据和悬停说明中。

建筑仅支持收到明确目标为基地 10／110、前哨 11／111 的 `Buff` 消息后显示。这是有消息才展示的兼容能力，不保证官方会给建筑发送该消息；协议没有单列建筑 Buff 消息，也不从 `base_status` 或阵地状态造出 Buff。之前删除的顶栏护盾与常驻 100% 防御图标不恢复。建筑 Buff 独立保存，不伪装成地面机器人，不影响八车枚举。

图标槽位固定，持续时间或位置更新只更新数据，不销毁组件。指挥手的地图标记也改为按固定接收车槽位复用，修复原先移动目标刷新导致整条标记销毁、重新从零坐标启动动画的闪烁。过期位置仍按原策略隐藏，不用过期坐标制造连续位置。

验证：`buffs` 检查真实数值、正负防御、缺字段、过期、retained、断线／换局、四个建筑 ID、操作手无位置时的本机栏、指挥手红蓝视角、等级左边缘对齐、原血条/车标间距和小窗口布局，并持续移动己方防御目标检查图标对象不被重建。截图在 `build/local-dev/tests/test-artifacts/map-buffs-*.png`。
