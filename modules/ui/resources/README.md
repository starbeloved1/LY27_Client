# 界面素材

`DamagePanel.qml` 参考 RM26 `DamagePanel.qml`（复旦大学星云 EGA 战队，MIT）的暗色浮层、金色标题和伤害统计行；`images/injury/` 的 `sundry_bullet.png`、`sundry_golf.png`、`sundry_icon.png` 从 RM26 `resources/models/images/` 独立复制。伤害分类按 2027 八个来源分别呈现，不复制旧模块假数据或旧统计分组。

maps/battlefield.png 为 1662 × 946 的场地高清重建版，来自工作区已生成的 battlefield-top-view-restored-v1.png。原始参考为 2027 比赛规则 V1.0.0 印刷页 29 的图 4-1。

该图经过 AI 高清重建，局部纹理、标线可能与原图不同，仅作为当前桌面底图。不能用它测量精确场地尺寸或直接确定世界坐标映射。

图片通过 Qt 资源系统编入桌面程序，底图仍为整张图片。机器人、设施点击、阵地光带及标记另以叠加层实现，不使用图像分割素材。

## RM26 参考素材

`images/` 中保留的顶部背景、基地血条、地图阵营圆环、朝向箭头、机器人编号及哨兵图标来自相邻项目 `RM26_Client/resources/models/images/`，保留对应相对目录；按用户要求暂时复用，用于当前信息展示。没有复制 RM26 的角色规则或 MQTT 处理逻辑。

`BaseHealthBar.qml` 与 `OutpostStatusBadge.qml` 参考 RM26 的同名组件，资源路径改为本项目内部路径；保留原基地素材、追血动画和前哨站卡片布局。基地上限为 10000，深色血槽和边框始终完整显示，只有亮色血量填充按当前血量 / 10000 裁切，5000 血对应半条。深色框不代表另一段血量，不使用 60% / 40% 容量叠加。未知值显示“—”并立即清空填充与追血段，保留完整血槽，不沿用旧赛季默认血量与重建次数。

`BaseHealthWing.qml` 参考 RM26 的完整侧翼组合接入 R 队徽、队名与基地血条。按用户要求，已移除防御增益文字、防御图标、血条无敌金边和相关动画，以及顶部基地状态行和“实时同步／等待数据”提示。宽屏整条顶部栏统一缩放，避免队徽与计时面板相互脱节；窄屏调整为两行。数据层的基地状态仍仅采用 2027 `base_status`，不移植旧版根据前哨站存活推断基地无敌的逻辑。

当前 `RobotMarker.qml` 按用户参考改为34 px 实心队色圆形车号、深色等宽编号、朝向小三角、中性细边血条和紧贴左侧的等级格，以 QML 绘制；不再使用原锁定圆环及编号图片，也不显示具体血量数字。血量比例未知时使用灰框问号。

地图前哨站复用 RM26 的 `minimap/red_map_outpost.png` 与 `blue_map_outpost.png`，素材已复制并编入本项目，运行不依赖 RM26。图标位于底图既有前哨中心，随视角镜像定位，图案保持正向；上方只画比车辆更细长的 72×8 血条。前哨站图标常规宽度为 62 px，小地图最多 33 px；图像提供器压低亮度并增加饱和度，保留渐隐柔光并与清晰主体分层叠加，压实队色主体并提清白色符号，沿自身轮廓加细描边，不添加光环，兼容软件渲染。基地图标按用户要求暂缓，地图基地血条也统一为无名称、无数字的细血条；顶部两侧仅保留基地血条、队徽和队名，移除前哨站卡片及血量，释放宽度给基地血条。

`MetricComparison.qml` 以 QML 绘制控制度和累计伤害的红蓝水平柱，双方共享刻度，仅在控制度标题右侧显示 C++ 按当前阵地占领计算的相对净速度，累计伤害不显示速度。正增速为绿色、负增速为亮红色，净增速以通信身份所属阵营为准。底板由 `BattleAnalysisPanel.qml` 统一提供，指标之间用细线分隔；当前经济为主读数，累计经济移至辅助行，科技与加密相邻分列，窄窗口将后勤整组放到两张图表下方。

比赛阶段素材复用 RM26 的 `gamephase/`，红蓝胜利序列来自 `resultpanel/`。为独立打包，红蓝原序列每四帧采样并保留最后一帧，各为 34 帧。统一以原图一半分辨率 960×540 保存 PNG，图案与透明度不重绘，40 ms 换帧后停留末帧。旧版异常素材的文字是“主裁判终止比赛”，没有用于 27 的泛化异常结束。`HudPanel.qml` 直接复用 RM26 切角面板，实现多项激活倒计时的相同表现形式；外部数据与阶段判断由 C++ 展示适配提供。

`BattleAnnouncementItem` 复用 RM26 `BattleMessageWidget` 的播报构图，`images/message/` 底框/前哨图标和 `images/robots/` 头像直接复制。`BattleAnnouncement.qml` 负责三秒显示与淡出，事件解析和连杀统计留在 C++。未复制参考仓库缺失的击杀音效。

地图协同增加 `MapMarkerMenu.qml`、`TacticalMarker.qml` 与 `TacticalSymbol.qml`。弹窗选择和符号绘制使用 QML，目标判断、接收者筛选、坐标转换、过期和指令提交在 C++ `TacticalMapController` 中；图标统一黄黑色，不与阵营颜色混用。车辆与设施仅在指挥手模式开放点击。见 `docs/tactical-map.md`。

`images/buffs/` 从 RM26 对应增益、弹药与地形图标独立复制。`BuffImageProvider` 裁出符号部分，去掉素材中的旧固定倍率文字；`BuffRow.qml` 固定七个类型槽位，避免倒计时刷新重建图标。地图车辆与设施的 Buff 均放在血条上方，与等级格／血条左侧对齐，原有血条与车标间距不变。操作手另有不依赖定位的本机增益栏。

`MatchNotices.qml` 汇总 27 固定节点、能量机关／飞镖结果及机制激活计时，使用 `MechanismNotices.qml` 横向排列 `BattleNoticeCard.qml` 节点／机制框和 `EventResultPanel.qml` 专用结果面板，放不下时换行并允许纵向滚动。`AnimatedNotice.qml` 以稳定消息 ID 管理入场、离场与补位：从上方模糊淡入、上移模糊淡出，离场结束后平移补位；秒数刷新不重播，断线及换局立即清理。模糊使用 Qt Quick Effects，仅在过渡期间启用，软件渲染保留位移和透明度动效。击杀/前哨摧毁图形播报固定覆盖在这些框上层。参考现有面板的暗底和事件配色，没有沿用 26 的旧事件编号或固定规则；数据筛选、时钟及生命周期统一在 C++ `MatchNotices` 中完成，不播放声音。原通用实时事件框已移除；飞镖结果相对己方绿／敌方红，能量完成事件按用户确认的己方范围统一绿色；结果面板只显示实际结果和有效详情。不接无人机被照射。

2026-11-07 的视觉整理通过 `UiTheme.hpp/.cpp` 与 `UiText.qml` 统一配色和字体：原图片资源保持不变，地图仅在显示层叠加暗色蒙层，顶部血条降低高度，宽度缩为侧翼的 82% 并移除黑色竖向刻度。金色主要用于指挥意图，普通标题与经济改为中性白；地图 Buff 仍完整放在血条上方。布局与实现取舍见 `docs/visual-design.md`。

地图专项整理见 `docs/map-marker-design.md`：底图运行时调色并缓存，PNG 原文件保持不变；36 px 深队色渐变车标使用白色编号、轻投影和带描边的朝向楔形，选中加金圈不改填充。地图设施血条为 72×8，与车辆的 42×12 血条区分；前哨亮度倍率为 0.84、饱和度倍率为 1.55，保留渐隐柔光并添加较轻的贴合轮廓细描边，不添加独立暗衬或光环。

`TerminalSettings.qml` 在右上角绘制小齿轮并显示角色／阵营设置，复用 `TechPanel` 与主题色；点击由 C++ `DesktopSession` 调用运行层身份切换，成功后替换展示适配，不在 QML 修改配置或通信。设置面板支持 Esc、点击外侧或齿轮关闭；全屏开关调用 `MapWindow::setFullScreen`，退出恢复原窗口大小或最大化状态，不影响后端。`Map.qml` 按底图宽高比决定地图栏尺寸，事件栏和分析板吸收横向／纵向余量，保留面板接缝。
