# 界面素材

`DamagePanel.qml` 参考 RM26 `DamagePanel.qml`（复旦大学星云 EGA 战队，MIT）的暗色浮层、金色标题和伤害统计行；`images/injury/` 的 `sundry_bullet.png`、`sundry_golf.png`、`sundry_icon.png` 从 RM26 `resources/models/images/` 独立复制。伤害分类按 2027 八个来源分别呈现，不复制旧模块假数据或旧统计分组。

maps/battlefield.png 为 1662 × 946 的场地高清重建版，来自工作区已生成的 battlefield-top-view-restored-v1.png。原始参考为 2027 比赛规则 V1.0.0 印刷页 29 的图 4-1。

该图经过 AI 高清重建，局部纹理、标线可能与原图不同，仅作为当前桌面底图。不能用它测量精确场地尺寸或直接确定世界坐标映射。

图片通过 Qt 资源系统编入桌面程序，底图仍为整张图片。机器人、设施点击、阵地光带及标记另以叠加层实现，不使用图像分割素材。

## RM26 参考素材

`images/` 中保留的顶部背景、基地血条、地图阵营圆环、朝向箭头、机器人编号及哨兵图标来自相邻项目 `RM26_Client/resources/models/images/`，保留对应相对目录；按用户要求暂时复用，用于当前信息展示。没有复制 RM26 的角色规则或 MQTT 处理逻辑。

`BaseHealthBar.qml` 与 `OutpostStatusBadge.qml` 参考 RM26 的同名组件，资源路径改为本项目内部路径；保留原基地素材、追血动画和前哨站卡片布局。基地上限为 10000，深色血槽和边框始终完整显示，只有亮色血量填充按当前血量 / 10000 裁切，5000 血对应半条。深色框不代表另一段血量，不使用 60% / 40% 容量叠加。未知值显示“—”并立即清空填充与追血段，保留完整血槽，不沿用旧赛季默认血量与重建次数。

`BaseHealthWing.qml` 参考 RM26 的完整侧翼组合接入 R 队徽与基地状态行。按用户要求，已移除防御增益文字、防御图标以及血条无敌金边和相关动画。宽屏整条顶部栏统一缩放，避免队徽与计时面板相互脱节；窄屏调整为两行。基地状态仅采用 2027 `base_status`，不移植旧版根据前哨站存活推断基地无敌的逻辑。

当前 `RobotMarker.qml` 按用户参考改为圆形车号、朝向小三角、金色细边血条和紧贴左侧的等级格，以 QML 绘制；不再使用原锁定圆环及编号图片，也不显示具体血量数字。血量比例未知时使用灰框问号。

地图前哨站复用 RM26 的 `minimap/red_map_outpost.png` 与 `blue_map_outpost.png`，素材已复制并编入本项目，运行不依赖 RM26。图标位于底图既有前哨中心，随视角镜像定位，图案保持正向；上方只画车辆同风格的细血条。前哨站图标常规宽度为 56 px，小地图最多 30 px；图像提供器在保持透明度的基础上提亮并增加饱和度，不添加光环，兼容软件渲染。基地图标按用户要求暂缓，地图基地血条也统一为无名称、无数字的细血条；顶部仅保留基地血条、队徽、队名和状态行，移除前哨站卡片及血量，释放宽度给基地血条。

`MetricComparison.qml` 以 QML 绘制控制度和累计伤害的红蓝水平柱，双方共享刻度，仅在控制度标题右侧显示 C++ 按当前阵地占领计算的相对净速度，累计伤害不显示速度。正增速为绿色、负增速为亮红色，净增速以通信身份所属阵营为准。科技与加密在经济卡片内相邻分组；窄窗口将这组放到两张图表下方。

比赛阶段素材复用 RM26 的 `gamephase/`，红蓝胜利序列来自 `resultpanel/`。为独立打包，红蓝原序列每四帧采样并保留最后一帧，各为 34 帧。统一以原图一半分辨率 960×540 保存 PNG，图案与透明度不重绘，40 ms 换帧后停留末帧。旧版异常素材的文字是“主裁判终止比赛”，没有用于 27 的泛化异常结束。`HudPanel.qml` 直接复用 RM26 切角面板，实现多项激活倒计时的相同表现形式；外部数据与阶段判断由 C++ 展示适配提供。

`BattleAnnouncementItem` 复用 RM26 `BattleMessageWidget` 的播报构图，`images/message/` 底框/前哨图标和 `images/robots/` 头像直接复制。`BattleAnnouncement.qml` 负责三秒显示与淡出，事件解析和连杀统计留在 C++。未复制参考仓库缺失的击杀音效。

地图协同增加 `MapMarkerMenu.qml`、`TacticalMarker.qml` 与 `TacticalSymbol.qml`。弹窗选择和符号绘制使用 QML，目标判断、接收者筛选、坐标转换、过期和指令提交在 C++ `TacticalMapController` 中；图标统一黄黑色，不与阵营颜色混用。车辆与设施仅在指挥手模式开放点击。见 `docs/tactical-map.md`。

`images/buffs/` 从 RM26 对应增益、弹药与地形图标独立复制。`BuffImageProvider` 裁出符号部分，去掉素材中的旧固定倍率文字；`BuffRow.qml` 固定七个类型槽位，避免倒计时刷新重建图标。地图车辆与设施的 Buff 均放在血条上方，与等级格／血条左侧对齐，原有血条与车标间距不变。操作手另有不依赖定位的本机增益栏。

`MatchNotices.qml` 提供 27 机会发放及 Event 3–16 的醒目视觉提示，参考现有面板的暗底和事件配色，没有沿用 26 的旧事件编号或固定规则；数据筛选、时钟及生命周期统一在 C++ `MatchNotices` 中完成，不播放声音。
